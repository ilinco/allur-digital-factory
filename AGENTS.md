## 1. Общие принципы взаимодействия
- **Приоритет существующей структуры:** Запрещено произвольно создавать новые каталоги верхнего уровня или изменять текущее соглашение о путях без явной команды.
- **Самодостаточность и безопасность:** Никогда не оставлять плейсхолдеры вроде `// TODO later` в логике валидации, безопасности и обработки ошибок.
- **Минимализм в изменениях:** Редактировать только те файлы, которые непосредственно относятся к поставленной задаче.

## 2. Backend: Архитектура, Безопасность и Тестирование

### 2.1. Слоистая архитектура (Layered / Clean Architecture)
Соблюдать строгую изоляцию слоев. Поток зависимостей всегда идет снаружи внутрь:
1. **Transport / Presentation Layer (Controllers, Handlers, Routers):**
   - Прием HTTP-запросов, сериализация/десериализация.
   - Валидация входных схем (DTO).
   - Вызов слоя бизнес-логики.
   - Запрещено: выполнение прямых запросов к БД, хранение бизнес-правил.
2. **Business Logic / Application Layer (Services, Use Cases):**
   - Оркестрация сценариев, транзакции, предметные правила.
   - Не зависит от HTTP-фреймворка, заголовков и сокетов.
3. **Data Access / Persistence Layer (Repositories):**
   - Непосредственное взаимодействие с базой данных, внешними API, кешем.
   - Возвращает предметные сущности или абстрактные структуры данных.

### 2.2. Безопасность и работа с секретами
- **Никаких секретов в репозитории:** Запрещено хардкодить токены, пароли, API-ключи, приватные сертификаты и строковые коннекты к БД.
- **Конфигурация:** Все чувствительные данные передаются исключительно через переменные окружения (`env`) и валидируются при старте приложения (schema validation).
- **Валидация и санитизация:** Любой пользовательский ввод должен проходить строгую валидацию типов, длины и формата перед передачей в сервисный слой. Использовать параметризованные запросы/ORM для исключения SQL/NoSQL инъекций.

### 2.3. Тестирование
- На **каждый** созданный или модифицированный эндпоинт **в обязательном порядке** пишутся автоматические тесты (интеграционные/e2e).
- Обязательный scope покрытия для каждого эндпоинта:
  - Успешный сценарий (`200 OK` / `201 Created`).
  - Ошибки валидации входных данных (`400 Bad Request` / `422 Unprocessable Entity`).
  - Проверка аутентификации и авторизации (`401 Unauthorized` / `403 Forbidden`).
  - Граничные условия и обработка отсутствующих ресурсов (`404 Not Found`).

## 3. Frontend: Архитектура компонентов и Структура

### 3.1. Декомпозиция компонентов
- **Лимит в 300 строк:** Если файл компонента превышает **300 строк кода** (включая JSX/TSX, стили и хуки), он считается спроектированным неверно.
- **Стратегия декомпозиции:**
  - Выносить сложную логику и сайд-эффекты в кастомные хуки (`use[Feature]`).
  - Дробить UI на компактные атомарные субкомпоненты.
  - Держать чисто презентационные элементы отдельно от контейнеров с состоянием.
- Соблюдать принцип единственной ответственности: один компонент решает ровно одну задачу.

### 3.2. Соблюдение файловой структуры
- Строго придерживаться утвержденной структуры проекта (Feature-Sliced Design или Domain-Driven):
  - Новые страницы размещаются только в директории `pages/` (или `app/`).
  - UI-кит общего назначения изолируется в `shared/ui/` (или `components/ui/`).
  - Специфичные фичи и их состояние изолируются в модули соответствующих фич.
- Запрещено засорять корень модулей разрозненными утилитами.

## 4. Frontend: Дизайн-система и Стили

### 4.1. Единая дизайн-система и сетка
- Все отступы, размеры шрифтов, радиусы скруглений и цвета берутся **только из предопределенных токенов** дизайн-системы (Tailwind theme / CSS Variables).
- **Строгая шкала отступов:** Использовать стандартизированный шаг (например, сетка на базе 4px/8px: `space-2` = 8px, `space-4` = 16px, `space-6` = 24px, `space-8` = 32px).
- Запрещено использовать произвольные значения отступов (никаких `margin: 17px` или `p-[19px]`).

### 4.2. Категорический черный список (STRICTLY FORBIDDEN)
Агенту **запрещено** генерировать, стилизовать или предлагать следующие паттерны:

1. **Градиенты на тексте:** Никаких `text-transparent bg-clip-text bg-gradient-to-...`, в том числе в секциях Hero и заголовках.
2. **Фиолетово-синие градиенты:** Категорический запрет на сочетания `indigo-to-purple`, `violet-to-blue` и аналогичные AI/Web3-клише.
3. **Emoji в интерфейсе:** Никаких эмодзи в качестве иконок, заголовков, пунктов меню или маркеров списков.
4. **Повсеместный шрифт Inter:** Не ставить `Inter` как дефолтное решение без явного указания. Использовать шрифт, зафиксированный дизайн-системой.
5. **Цветные рамки карточек:** Запрещены неоновые, яркие, акцентные или радужные границы (`border-blue-500`, `border-purple-400` и т.д.). Границы только нейтральные и приглушенные.
6. **Glassmorphism:** Никаких полупрозрачных матовых карточек (`backdrop-blur`, полупрозрачный белый/черный с размытием фона).
7. **Низкоконтрастная темная тема:** Недопустимы серый текст на темно-сером фоне, плохая читаемость и провалы по WCAG AA/AAA.
8. **Паттерн «3 иконки в ряд»:** Не использовать шаблонную композицию из трех одинаковых плашек/иконок в одну строчку для описания фич.
9. **Избыточные badge:** Запрещено навешивать бейджи, теги и метки на каждый заголовок, карточку или пункт списка.
10. **Иконки Lucide Icons:** Использовать только согласованный проектный пак иконок (Heroicons, Tabler, Phosphor или собственный SVG-набор), избегая дефолтного Lucide.
11. **Fade-in анимации на скролле:** Никаких тяжелых и раздражающих анимаций появления (`fade-in`, `slide-up` при прокрутке страницы).
12. **Градиентные кнопки при hover:** Никаких переливающихся градиентов на кнопках при наведении. Состояния кнопок должны меняться дискретно через контраст или прозрачность.
13. **Непостоянные отступы:** Запрещено смешивать разные шаги сетки внутри одной секции или страницы.
14. **Нелепый/шаблонный текст:** Никаких generic-фраз («Раскройте потенциал вашего бизнеса», «Инновационное решение нового поколения», «Магия AI»). Текст интерфейса должен быть лаконичным, предметным и информативным.
15. **Курсивные акценты с засечками (Serif italic):** Запрещено использовать шрифты с засечками курсивом для выделения отдельных слов в заголовках.
